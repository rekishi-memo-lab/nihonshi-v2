# 知識台帳の仕様案（V2・案）

知識台帳は、V2 の教材づくりの中心になるデータ。授業・一問一答・図表・テーマ史は、台帳の知識を組み合わせて作る。
**この文書は案。** 形式を確定する前に、1つの時代で試作して見直す。

- データ形式：`docs/ledger/schema.json`（JSON Schema）
- 記入例：`docs/ledger/example.json`（形式を示すための例。中身の根拠は確かめていない）

---

## 1. 基本の考え方

1. **1件＝1つの知識。** 用語・出来事・人物・制度・法令・作品・場所・史料などを1件ずつ登録する。授業1講は、何件もの知識を組み合わせて作る。
2. **3つの判断を混ぜない。** 「教科書に載っているか」「入試でどれだけ重要か」「理解にどこまで説明が要るか」は別々の項目で持つ（`docs/education-policy.md` §4）。過去問での確認状況も別に持つ。
3. **知識どうしのつながりは「関係」として別に持つ。** 背景・原因・結果・対立・継承・比較などを、知識と知識をつなぐ線（関係）として登録する。ある知識から関連する知識へたどれるようにする。
4. **根拠と確認の状況を必ず持つ。** 確かめていないものは「未確認」のまま残す。空欄を「なし」と区別する。
5. **教科書や過去問の本文は写さない。** ページや設問の場所と、自分の言葉の要約だけを書く。

## 2. 知識の項目

| 項目 | キー | 内容 | 値の例 |
|---|---|---|---|
| 知識ID | `id` | 一度つけたら変えない・再利用しない | `K000123` |
| 種類 | `type` | 何についての知識か | 用語／出来事／人物／制度／法令／作品／場所／集団／史料／概念 |
| 名称 | `name` | 見出し語 | 承久の乱 |
| 別名 | `aliases` | 別の呼び方・表記 | 承久の変 |
| 読み方 | `reading` | ひらがな | じょうきゅうのらん |
| 読みの確認 | `reading_status` | 読みを辞書などで確かめたか | 確認済み／未確認 |
| 時代 | `era` | 大きな時代区分 | 原始／古代／中世／近世／近代／現代 |
| 時期 | `period` | 細かい時期 | 鎌倉時代 |
| 年代 | `date` | 始まり・終わり・表示用の文字・精度 | `{"start":"1221","end":"1221","label":"1221年","precision":"年"}` |
| 分野 | `fields` | 複数可 | 政治／外交／経済／社会／文化／思想・宗教 |
| 基本説明 | `summary` | 一言で何か（自分の言葉で） | |
| 背景・原因 | `background` | 文章での説明。つながる知識は「関係」でも結ぶ | |
| 結果・影響 | `result` | 同上 | |
| 教科書の記載 | `textbook` | 記載の有無・場所・確認の状況（§3） | |
| 入試での重要度 | `importance` | 試験ごとの段階と、その判断の根拠（§4） | |
| 過去問の根拠 | `exam_evidence` | 出題の記録（§5） | |
| 説明の深さ | `depth` | 理解のために要る説明の深さ | 名前のみ／一文／因果／構造 |
| つまずき | `pitfalls` | 混同しやすい点・誤解しやすい点 | |
| 授業での扱い | `lessons` | 初めて詳しく扱う講、再登場する講とその目的、テーマ史（§6） | |
| 関連問題 | `quiz_ids` | 一問一答などの id | |
| 図表・地図・動画 | `media` | 使う図表などの id | |
| V1 での出どころ | `v1_refs` | V1 のセットid・授業番号・問題id（移行の追跡用） | `{"pack":"chusei2","lesson":"05","quiz":[40]}` |
| 検証の状況 | `verification` | 状態・最終確認日・メモ | 下書き／根拠確認中／確認済み／要修正 |
| 未解決の疑問 | `open_questions` | まだ答えが出ていない点 | |
| 異説 | `disputes` | 説が分かれる点と、その扱い | |

関連する知識は、知識の項目の中ではなく「関係」（§7）で持つ。

## 3. 教科書の記載（`textbook`）

| キー | 内容 | 値 |
|---|---|---|
| `status` | どこに載っているか | 本文／注／図版・説明文／史料／コラム／記載なし／未確認 |
| `book` | 教科書名と版 | 例：山川出版社『詳説日本史』（版は確認してから書く） |
| `pages` | ページ（複数可） | `[176, 177]` |
| `location` | ページの中の場所（自分の言葉で） | 「節の見出しの直後」など |
| `check.method` | 何で確かめたか | 原本／画像／OCR／未確認 |
| `check.ocr_reliability` | OCR で読んだときの信頼度 | 高／中／低／不明 |
| `check.checked_at` | 確かめた日 | `2026-11-23` |

- 「記載なし」は、範囲を全部読んで見つからなかったときだけ使う。読んでいないときは「未確認」。
- 教科書の文章そのものは書かない。

## 4. 入試での重要度（`importance`）

試験の種類ごとに、別々に持つ。

```json
"importance": {
  "kyotsu":   {"level": "必須", "basis": "根拠の説明", "provisional": true},
  "shidai":   {"level": "頻出", "basis": "…", "provisional": true},
  "nankan":   {"level": "標準", "basis": "…", "provisional": true}
}
```

- `level`：必須／頻出／標準／発展／対象外／未判定
- 試験の種類のキーは、`kyotsu`（共通テスト）、`shidai`（私大の標準）、`nankan`（難関私大）を基本にする。特定の大学・学部を足すときは、`<大学>_<学部>` の形で**大学と学部を分けたキー**にする（例：`univa_keizai`）。
- `provisional`：過去問の根拠（§5）がそろうまでは `true`（暫定）。
- 回数だけで決めない。`basis` に「何回、どの役割で出たか」「教科書の扱い」「理解の要・不要」など、判断の理由を書く。

## 5. 過去問の根拠（`exam_evidence`）

出題1件ごとに1つ書く。問題文は写さない。

| キー | 内容 | 値の例 |
|---|---|---|
| `exam` | 試験 | 共通テスト本試験／〇〇大学 〇〇学部 |
| `year` | 年度 | 2025 |
| `question` | 設問の場所 | 大問2 問3 |
| `role` | その知識が問題の中でどう出たか | 正解／選択肢（正解以外）／リード文／設問文／史料／図表／解答の根拠／講評での言及 |
| `source` | 何で確かめたか | 原本／二次資料（解答速報など）／未確認 |
| `checked_at` | 確かめた日 | |

- 回数（「何回出たか」）は、この記録から計算する。手で書かない。
- 同じ知識が、ちがう設問で何度も問われたかも、この記録からわかる。

## 6. 授業での扱い（`lessons`）

```json
"lessons": {
  "first": "L024",
  "reappear": [
    {"lesson": "L029", "purpose": "因果の回収", "note": "後醍醐天皇の倒幕で力関係が再び問われる"}
  ],
  "theme": [{"lesson": "T-hosei-04", "purpose": "比較"}]
}
```

- `first`：初めて詳しく扱う講（1つだけ）。
- `reappear.purpose`：想起／比較／因果の回収／発展／伏線。目的の書けない再登場は、意味のない重複の候補になる。
- 講の id は、カリキュラムが決まってから付ける。決まるまでは仮の id を使う。

## 7. 知識どうしの関係（`relations`）

関係は、知識とは別のファイルに「線」として1本ずつ登録する。
**向き**は「A（`from`）は B（`to`）の〜である」と読む。

| 種類 `type` | 読み方 | 逆向きに見たとき | 例 |
|---|---|---|---|
| 背景 | A は B の背景 | B の背景は A | 荘園の拡大 → 院政 |
| 原因 | A は B の原因 | B の原因は A | 実朝の暗殺 → 承久の乱 |
| 契機 | A は B のきっかけ | B のきっかけは A | |
| 結果 | A は B の結果 | B の結果は A | 六波羅探題の設置 → 承久の乱 |
| 影響 | A は B に影響した | B は A の影響を受けた | |
| 対立 | A は B と対立した | （同じ） | 後鳥羽上皇 ↔ 北条義時 |
| 継承 | A は B を受け継いだ | B は A に受け継がれた | |
| 前身 | A は B の前身 | B は A の後身 | |
| 比較 | A は B と比べるとよい | （同じ） | |
| 混同注意 | A は B とまちがえやすい | （同じ） | 新補地頭 ↔ 本補地頭 |
| 担い手 | A は B を行った・作った | B を行ったのは A | 北条泰時 → 御成敗式目 |
| 構成要素 | A は B の一部 | B は A をふくむ | |
| 同時期 | A は B と同じ時期 | （同じ） | |

各関係には次も持たせる：`note`（どういう関係かの一言）、`evidence`（根拠）、`status`（下書き／確認済み）。

これで、ある知識から「原因をさかのぼる」「結果をたどる」「混同しやすいものを並べる」といった道筋を、プログラムで作れる。年代整序や正誤問題の材料にも使える。

## 8. ファイルの置き方（案）

```
ledger/
  knowledge/kodai.json      … 時代ごとの知識（配列）
  knowledge/chusei.json
  …
  relations.json            … 関係（配列）
  exams.json                … 試験の一覧（試験のキーと名前）
```

- 1つのファイルが大きくなりすぎたら、時期ごとに分ける。
- 形式のチェック（JSON Schema）と、つじつまのチェック（存在しない id への参照がないか、`first` が1つか、目的のない再登場がないか、など）をスクリプトで行う。
- 台帳は公開リポジトリに置く。過去問の原本や教科書の本文は入れない（`CLAUDE.md` §7）。

## 9. まだ決めていないこと

- 講の id の付け方（カリキュラム確定後）。
- 試験の種類のキーをどこまで細かくするか（共テの本試・追試、私大の学部など）。
- 人物の扱い（1人を1件にするか、役職ごとに分けるか）。
- 1件の粒度（「承久の乱」と「新補率法」を別の件にするか、など）。試作で決める。
- 台帳から授業・問題を作る手順と、その確認のしかた。
